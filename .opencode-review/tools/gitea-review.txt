Submit a code review on a Gitea/Forgejo pull request.

This tool submits a review with:
1. A summary/report (AI-generated, displayed as the main review body)
2. Line-level comments attached to lines the pull request adds or deletes
3. An approval decision (approve/comment/request_changes)

**IMPORTANT**: The `summary` parameter should contain a complete, well-formatted review report. 
The tool does NOT auto-generate content - you control the entire output.

## Summary Format (Recommended)

Generate a summary organized by severity level:

\`\`\`markdown
## Code Review Report

### 📋 Overview
[Brief summary of PR changes and overall code quality assessment]

### 🔴 Critical Issues (CRITICAL)
> Must fix before merge

| Issue | File | Description |
|:------|:-----|:------------|
| Plaintext password logging | `login.post.ts:12` | Password printed to logs in plaintext, severe security violation |
| Hardcoded JWT secret | `auth.ts:4`, `token.ts:4` | Secret key hardcoded, attackers can forge any token |

### 🟠 High Priority (HIGH)
> Should fix before merge

| Issue | File | Description |
|:------|:-----|:------------|
| Privilege escalation | `user/index.put.ts:27` | Users can set their own `isAdmin` status |

### 🟡 Medium Priority (MEDIUM)
> Recommended to fix

| Issue | File | Description |
|:------|:-----|:------------|
| Password bypass | `login.post.ts:39` | Plaintext password comparison used |

### 🟢 Low Priority (LOW)
> Optional improvements

| Issue | File | Description |
|:------|:-----|:------------|
| Code style | `utils.ts:15` | Use const instead of let |

### 💡 Suggestions
[Overall recommendations and improvement directions]
\`\`\`

**Notes**:
- Only include severity sections that have issues (omit empty sections)
- File column should include path and line number
- Description should briefly explain the issue and its impact

## Line Comments

Use structured tags for categorization:
- `**[BUG:HIGH]**` - Bug with severity
- `**[SECURITY:CRITICAL]**` - Security issue
- `**[PERFORMANCE:MEDIUM]**` - Performance concern
- `**[STYLE:LOW]**` - Style suggestion

Categories: BUG, SECURITY, PERFORMANCE, STYLE, DOCS, TEST
Severities: CRITICAL, HIGH, MEDIUM, LOW

## Where Comments Can Go

Inline comments can only be attached to lines the pull request adds (`[NEW:X] +`, use `line: X`) or deletes (`[OLD:X] -`, use `old_line: X`). Context lines cannot take a comment.

Every comment must include `anchor_text`: the code on the line it is about, copied exactly from the diff without the `[NEW:X]` or `[OLD:X]` prefix. The tool checks the line number against it and moves the comment to the line that matches if the number is wrong.

A finding about unchanged code, such as a caller that the change breaks, belongs in the summary, or on the changed line that causes it. A comment that cannot be attached to a changed line is listed in the summary instead of being posted inline.

## Example Usage

\`\`\`json
{
  "summary": "## Code Review Report\n\n### 📋 Overview\nThis PR adds user authentication. Overall implementation is clean, but has 1 critical security issue and 1 medium performance issue.\n\n### 🔴 Critical Issues (CRITICAL)\n> Must fix before merge\n\n| Issue | File | Description |\n|:------|:-----|:------------|\n| Plaintext password storage | `src/auth.ts:25` | Password stored without hashing, severe security risk |\n\n### 🟡 Medium Priority (MEDIUM)\n> Recommended to fix\n\n| Issue | File | Description |\n|:------|:-----|:------------|\n| Database connection leak | `src/db.ts:58` | Connection not closed, may exhaust connection pool |\n\n### 💡 Suggestions\nFix all security issues before merge, especially password storage.",
  "comments": [
    {
      "path": "src/auth.ts",
      "line": 25,
      "anchor_text": "user.password = password;",
      "body": "**[SECURITY:CRITICAL]** Password should be hashed using bcrypt.",
      "suggestion": "const hash = await bcrypt.hash(password, 10);"
    }
  ],
  "approval": "request_changes"
}
\`\`\`

## Parameters

- summary: Complete review report content (required) - AI generates this
- comments: Array of line-level comments (optional), each with path, line or old_line, anchor_text, body, and an optional suggestion
- approval: "comment" (default), "approve", or "request_changes"
